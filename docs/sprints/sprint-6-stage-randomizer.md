# Sprint 6: Stage Randomizer

**Priority:** Lower — high complexity, benefits from other sprints being done first
**Complexity:** High
**New AP Item IDs:** None (stages already have IDs; this shuffles the mapping)
**Depends On:** Sprint 1 (all stages registered), Sprint 2 (check prioritization works with shuffled stages), Sprint 3 (portal control independent of stage order)

## Goal

Randomize which stages appear at which tier. Stage 1 areas might show up in the Stage 3 slot and vice versa, creating a completely different pacing experience for each seed. Boss stages and hidden realms stay fixed.

## Constraints

- **Boss stages stay as boss stages**: Commencement, The Planetarium, Prime Meridian, Solutional Haunt, Neural Sanctum
- **Hidden realms stay as hidden realms**: Bazaar, Void Fields, Gilded Coast, A Moment, etc.
- **Each slot must have at least 1 stage**: No empty tiers
- **A stage can only appear in one slot**: No duplicates across tiers
- **Stage 5 gets Primordial Teleporter**: Regardless of which stages are in Slot 5, the teleporter type must support routing to Commencement/final bosses

## Phase 1: Stage Mapping Generation (Python Side)

The mapping must be generated by the Python world so both client and server agree on the shuffle.

### Algorithm
```python
def generate_stage_mapping(self):
    # Collect all regular stages (filtered by DLC toggles)
    all_stages = list(base_stages)
    if self.options.dlc_sotv: all_stages.extend(sotv_stages)
    if self.options.dlc_sots: all_stages.extend(sots_stages)
    if self.options.dlc_ac:   all_stages.extend(ac_stages)

    self.random.shuffle(all_stages)

    # Distribute into 5 slots, ensuring at least 1 per slot
    slots = {1: [], 2: [], 3: [], 4: [], 5: []}
    for i, stage in enumerate(all_stages):
        slot = (i % 5) + 1
        slots[slot].append(stage)

    return slots
```

## Phase 2: Override Stage Selection (C# Side)

### Tasks
1. Create `Handlers/StageRandomizerHandler.cs`
2. Parse `stageMapping` from slot data in `ArchipelagoClient.cs`
3. Build `Dictionary<int, List<SceneDef>>` mapping slot number to scene defs
4. Hook `Run.PickNextStageScene` to use the randomized mapping

### Implementation
```csharp
public class StageRandomizerHandler
{
    private Dictionary<int, List<SceneDef>> slotToScenes = new();
    private bool enabled = false;

    public void Initialize(Dictionary<string, List<string>> mapping)
    {
        enabled = true;
        foreach (var kvp in mapping)
        {
            int slot = int.Parse(kvp.Key);
            slotToScenes[slot] = kvp.Value
                .Select(name => SceneCatalog.FindSceneDef(name))
                .Where(def => def != null)
                .ToList();
        }
    }

    public void Hook()
    {
        On.RoR2.Run.PickNextStageScene += Run_PickNextStageScene;
    }

    private void Run_PickNextStageScene(
        On.RoR2.Run.orig_PickNextStageScene orig,
        Run self,
        WeightedSelection<SceneDef> choices)
    {
        if (!enabled)
        {
            orig(self, choices);
            return;
        }

        int currentSlot = DetermineCurrentSlot(self);
        if (slotToScenes.TryGetValue(currentSlot, out var scenes))
        {
            choices.Clear();
            foreach (var scene in scenes)
            {
                if (self.CanPickStage(scene))
                    choices.AddChoice(scene, 1f);
            }
        }

        // If no valid choices (all blocked), fall back to original
        if (choices.Count == 0)
            orig(self, choices);
        else
            orig(self, choices); // Let orig handle final selection from our choices
    }

    private int DetermineCurrentSlot(Run run)
    {
        // Stage count is 0-indexed in RoR2
        // Stages cycle 1-5, so slot = (stageCount % 5) + 1
        // But Run.stageClearCount gives completed stages
        int nextStage = (run.stageClearCount % 5) + 1;
        return nextStage;
    }
}
```

- New: `Archipelago.RiskOfRain2/Handlers/StageRandomizerHandler.cs`

## Testing Criteria

1. **Mapping determinism**: Same AP seed produces the same stage mapping every time
2. **Boss stages preserved**: Commencement, Planetarium, Prime Meridian, Neural Sanctum never appear in regular slots
3. **Teleporter swap**: Slot 5 always has Primordial Teleporter, regardless of which stages are there
4. **Regular teleporter**: Slots 1-4 have regular Teleporter, even if Sky Meadow is in that slot
5. **Blocked stages**: Blocked stages remain blocked even if randomized to a different slot
6. **Location checks**: Location checks work correctly with shuffled stages (IDs are per-scene, not per-slot — should be automatic)
7. **Hidden realms**: Hidden realms unaffected by randomizer
8. **Full loop**: Complete all 5 slots. Verify the game loops correctly and uses the same mapping
9. **Disabled**: Set `stageRandomizer=false`. Verify normal stage progression
10. **Check prioritization**: Verify Sprint 2's weighted selection still works with randomized stages

## Risks and Open Questions

- **Difficulty scaling**: RoR2 scales difficulty with time and stage count, not with specific stages. Putting a visually "hard" Stage 4 area in Slot 1 means enemies are at Slot 1 difficulty — easy to fight, but the environment may be confusing for new players. Is this desirable?
- **Scene-specific interactables**: Some stages have unique features:
  - **Sky Meadow**: Artifact Portal — does it appear regardless of which slot Sky Meadow is in?
  - **Siren's Call**: Alloy Worship Unit egg event — tied to the scene, not the slot
  - **Abandoned Aqueduct**: Buried Chamber event
  - **Recommendation:** Scene-specific events travel with the scene, not the slot
- **Primordial Teleporter**: Swapping teleporter prefabs is non-trivial. The Primordial Teleporter in non-Sky-Meadow stages may have visual/positioning issues. Need thorough testing
- **Loop behavior**: After loop, does the mapping persist? **Recommendation:** Yes — same mapping for the entire session
- **Hook ordering**: Both `StageRandomizerHandler.Run_PickNextStageScene` and `StageBlockerHandler.Run_PickNextStageScene` hook the same method. Registration order determines wrap order. Register StageRandomizerHandler FIRST (builds choices), then StageBlockerHandler SECOND (filters blocked stages)
- **Interaction with Sprint 2**: Check prioritization adds weight to stages with remaining checks. This should still work because it operates on the weighted selection after it's been built, regardless of which stages are in which slots
- **Explore mode implications**: In explore mode, each environment has specific check counts. The location IDs are per-scene, not per-slot, so they should work correctly regardless of slot assignment. But the StageBlockerHandler's environment unlock system needs to match the new slot assignments
